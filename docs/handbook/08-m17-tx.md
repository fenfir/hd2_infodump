# 08. M17 TX (MCU-baseband pump)

## What it is / how it works

M17 on the HD2 is an **MCU-baseband** mode, like every OpenRTX target: software on the CK803S generates the 4FSK waveform (Codec2 voice → LSF (Link Setup Frame) / stream framing → conv-code + interleave → ±1/±3 symbols) and the SoC only modulates and keys the RF. There is no hardware M17 framer anywhere — the HR_C7000 DMR Layer-2 modem is DMR-framed-only silicon and cannot carry M17, so almost nothing from the [DMR-modem bring-up](06-dmr-tx) transfers. What reuses is the RF backend (AT1846S keying, PA bias, APC DAC, tune) and the OpMode dispatch.

The name "MCU-baseband pump" describes the injection mechanism, and the HD2 has **two** of them — this is the load-bearing subtlety of the whole chapter:

1. **The 8 kHz FM-TX-RAM pump** (the original "pump"): `AUDIO_CONTROL` (`0x11000080`) bit0 `tx_voice_source` = 1 (register `0x11000080` = `AUDIO_CONTROL` = `VOICE_PATH` = `SOCSYS_VOICE_PATH`; bit0 = `tx_voice_source` = `VOICE_PATH_SRC_TXRAM` — same register/bit named across chapters [03](03-audio-path)/[06](06-dmr-tx)) makes the C7000 FM modulator read CPU-written PCM from the `0x16000030` / `0x16000230` ping-pong instead of the mic ADC. Proven on air (2026-06-19) to carry arbitrary baseband, but the buffer is drained at a **fixed 8 kHz** (256 s16 samples = 32 ms/half). At M17's 4800 sym/s that is ~1.67 samples/symbol — enough for **LICH (Link Information Channel) sync but never a full LSF lock**. Multiple attempts to raise the rate all failed (see Gotchas).
2. **The native 4FSK PHY** (the path that actually works): the C7000 modem's 4FSK modulator is separable from the DMR L2 framer. `WORK_MODE` (`0x11000100`) layermode `[4:3]=0` = physical-layer mode emits raw symbols straight from modem TX-RAM (`SEND_DATA0=0x16000000` / `SEND_DATA1=0x16000024`) with **no framing/FEC/sync/TDMA**, at the native **38.4 kHz** symbol clock (8 samples/symbol). This cleared the 8 kHz wall: on 2026-06-20 an off-air `m17-demod` decoded a full LSF (`SRC: AB1CDE, DEST: N0CALL, STR:V/V`) through this path. **This is the settled TX path for M17 voice.**

Codec2-3200 fixed-point (`C2_FIXED`) encodes in **14.5 ms/frame** on the real CK803S — under the 20 ms budget — so live M17 voice *is* viable (the earlier "voice is dead" conclusions were compiling the float path; see Gotchas, and the [voice codecs chapter](07-voice-codecs) for the encode-vs-decode budget). One key shortcut: M17's `byteToSymbols` LUT (`{+1,+3,-1,-3}`, MSB-first) is byte-identical to HR_C7000 §9.5.2, so the M17 `frame_t` bytes are already the PHY dibit format — feed them verbatim and skip the `Modulator`/48 kHz baseband entirely.

## How to implement it

**Voice path (native 4FSK PHY — the working one, diag op `'s'`, `dmr_HD2.cpp` `hd2_m17_phy_*`):**

1. Encode voice: `codec2_encode` with `C2_FIXED` (14.5 ms/frame), 2×20 ms frames → one M17 stream payload per 40 ms.
2. Frame it with the vendored OpenRTX M17 stack: `LSF setSource/setDestination/setType` → `FrameEncoder::encodeLsf` / `encodeStreamFrame` → `frame_t` bytes.
3. **Skip the Modulator/baseband** — the frame bytes are already PHY dibits (2 bits/symbol, MSB-first, 4 symbols/byte, §9.5.2 map: 00→+1, 01→+3, 10→−1, 11→−3). 36 bytes = 144 symbols = 30 ms.
4. Arm the PHY (values that work):
   - `SOFT_RSTN` the modem
   - `WORK_MODE` (`0x11000100`) = **`0x02` CONTINUOUS** (NOT `0x22` timeslot — `0x22` left the engine idle even with SLOTON; vendor L1-TX sites all use `0x02`)
   - `LAYER2_CONTROL` (`0x11000400`) = `0x82`
   - `LAYER2_TXRX_CTRL` (`0x11000408`) = `0x81`
   - `RF_MODE` (`0x11000104`) = two-point modulation
   - AT1846S `0x40` = `0x31` (digital path); deviation trim via `RF_MOD_BIAS_CTRL` (`0x11000114`), which packs the reduce byte `dev` into `[15:8]`/`[7:0]` (M17 ≈ 1.235× DMR deviation; observed working `dev=12`, a *lower* reduce than DMR's `0x19` = more deviation). Note: the native-PHY path sets deviation via `RF_MOD_BIAS` only — it does not touch AT1846S `0x59` (that is the analog-FM deviation register)
   - Reuse the proven DMR-TX RF keying / PA backend (shared `hd2_fm_tx_key` / `hd2_fm_tx_unkey` from the [FM analog chapter](04-fm-analog), mirroring `OpMode_M17::txState`)
5. Write symbols to the ping-pong banks `SEND_DATA0`=`0x16000000` / `SEND_DATA1`=`0x16000024`.
6. **Refill is TIME-PACED, not hardware-strobed.** In continuous L1 no bank strobe is exposed (`TS_TX`/`MODEM_IRQ`/`SLOT_PRE`/`LAYER2_STATUS` all stay 0). Refill the idle bank on **absolute deadlines** (`t0 + N*30ms`) — cumulative `sleep(30)` drifts and tears frames. **Refill phase matters hugely**: phases 3 ms and 9 ms locked the LSF; most other phases gave LICH-only.
7. Sequence per transmission: PTT → preamble → LSF → stream frames → EOT.

**Legacy 8 kHz FM-TX-RAM pump (LICH-only, diag op `'f'`/`'Y'`):** `WORK_MODE[7]=1` (FM modulator) + `FM_PTT` (`0x11000560`, bit0=1 keys the modem FM-TX engine) + `AUDIO_CONTROL` (`0x11000080`) bit0=1 (`VOICE_PATH_SRC_TXRAM`) + AT1846S keyed + linearise the FM path (`FM_BANDWIDTH` `0x11000500`: pre-emphasis OFF `[4]`, wide `[3]`; `FM_DEV_COEF` `0x11000504`). Refill the `0x16000030`/`0x16000230` ping-pong synced to `FM_ADDR_SW` (`0x1100056c`, RO: 1=low half, 2=high half). Use only for tone/BER bring-up — it does not reach full LSF lock.

## Gotchas & cautions

- ⚠️ **Don't use the 8 kHz FM-TX-RAM pump for real M17 voice.** It only ever reaches LICH sync; the 1.67 samples/symbol coarseness + analog FM round-trip keeps the symbol-error floor above the LSF-CRC threshold. The native 4FSK PHY (`WORK_MODE=0x02`) is the answer.
- ⚠️ **Runtime FM-TX-RAM rate-raising fails** — the 8 kHz divider (`clk_8k_div_num`, `CLK_MGR 0x11000020` `[24:13]`) only relatches at boot-time soft-reset, so it never shifts modem FM-TX-RAM consumption at runtime.
- ⚠️ **Dead end — the DMR modem framer.** It is DMR-framed-only; it exposes no M17 mode and no symbol stream. Only the modem's raw 4FSK *modulator* (layermode 0) is reusable.
- ⚠️ **M17 voice IS viable — build with `C2_FIXED` + a clean rebuild** (`rm -rf build-docker`); the earlier "not viable" result came from silently compiling the FLOAT codec2 path on stale incremental builds. With `target_compile_definitions(... C2_FIXED)`, encode = 14.5 ms/frame.
- ⚠️ **qemu Cortex-M3 is not a CK803S proxy** — instruction counts don't transfer (different ISA/CPI); benchmark on-device.
- **`hd2_m17.ld` is mandatory for any M17 build.** Codec2's ~12 KB static `codec2_t` (`.bss`) shrinks the ~39 KB heap below the boot threshold → UI splash hang. This linker script keeps the RAM origin at the committed default `0x20000` (the uncommitted DMR-voice `hd2.ld` variant instead *raises* origin `0x20000`→`0x33000`; see [voice codecs chapter](07-voice-codecs)) and reuses the 76 KB AMBE window for heap (→ ~119 KB). Select `-DMIOSIX_LINKER_SCRIPT=hd2_m17.ld`; **valid ONLY with `HD2_DMR_VOICE=OFF`** (it reuses the AMBE code window — collides otherwise).
- **No sleeps in the pump/refill path** — wedges the tickless core (memory `hd2-fm-tx-ptt-and-lockups`). Use static buffers, not stack.
- **Intermittent full lock** remains: even at the best refill phase, roughly 1 LSF lock per 6 s — a residual per-bank switch glitch (waterfall striping) tears most frames. Tightening the refill (kill the bank-switch glitch/drift) is the open work for reliable continuous lock + intelligible voice.
- **FM-TX-RAM RAM is 8-bit** — byte writes, big-endian (low addr = hi byte); an unaligned word store hangs SAHB (memory `hd2-fm-voice-tx-solved`).
- **The pump occasionally warm-reboots mid-TX** (~1 in 3–4 runs; shared with diag ops `'f'`/`'s'`).
- **Codeplug:** the radio's idle channel must be FM (not DMR) or it TXes on the wrong freq/config. Use `vendor/dmrconfig` (`hd2.c` backend) with the bridge DOWN (port contention).

## Where the code lives

- `vendor/OpenRTX/platform/targets/HD2/m17_blob_HD2.S` — embedded host-generated M17 test frame (`.incbin "m17_frame.raw"`), played through the 8 kHz pump for diag op `'f'`.
- `vendor/OpenRTX/platform/targets/HD2/hd2_m17.ld` — low-RAM-origin linker script (mandatory for M17 builds).
- `vendor/OpenRTX/platform/drivers/baseband/dmr_HD2.cpp` — `hd2_m17_phy_tx_start` / `hd2_m17_phy_stage` / `hd2_m17_phy_tx_stop` (native 4FSK PHY; the `WORK_MODE=0x02`, `LAYER2_CONTROL=0x82`, `LAYER2_TXRX_CTRL=0x81` arm).
- `vendor/OpenRTX/platform/targets/HD2/hd2_diag.cpp` — `m17_voice_worker` (op `'s'` `m17_voice`, calls the `hd2_m17_phy_*` above), `m17_txtest` (op `'f'`), `fm_tx_tone_test` (op `'Y'`, 8 kHz pump), `codec2_selftest_worker` (op `'i'`).
- `vendor/wt-hd2-vp-adpcm/openrtx/src/protocols/M17/` — vendored M17 stack (`FrameEncoder`, `Modulator`, `LinkSetupFrame`, `Golay`, `Callsign`).
- `vendor/wt-hd2-vp-adpcm/openrtx/src/rtx/OpMode_M17.cpp` (+ `include/rtx/OpMode_M17.hpp`) — TX/RX FSM.
- `vendor/Codec2-mod/` — M17-Project's malloc-free, fixed-point (`C2_FIXED`) codec2 fork.
- `vendor/OpenRTX/platform/targets/HD2/hd2_regs.h` — register names (`SOCSYS_VOICE_PATH`/`VOICE_PATH_SRC_TXRAM`, `SOCSYS_WORK_MODE`, `SOCSYS_LAYER2_*`, `SOCSYS_FM_PTT`, etc.).
- Build wiring: `vendor/OpenRTX/platform/targets/HD2/CMakeLists.txt` — `HD2_M17` / `HD2_M17_VOICE` options (both default OFF; `HD2_M17_VOICE` implies `HD2_M17`; both need `-DMIOSIX_LINKER_SCRIPT=hd2_m17.ld`).

*(⚠️ Two trees: the HD2-specific M17 glue — `m17_blob_HD2.S`, `hd2_m17.ld`, `hd2_diag.cpp`, `hd2_regs.h` (all under `vendor/OpenRTX/platform/targets/HD2/`) and `dmr_HD2.cpp` (under `vendor/OpenRTX/platform/drivers/baseband/`) — currently lives ONLY on the M17 branch checked out at `vendor/OpenRTX/`. Paths above are pointed at whichever tree actually carries the file.)*
